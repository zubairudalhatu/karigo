# Controlled drill failure and rollback guide

## Immediate response

1. Stop creating new requests.
2. If safe and authorised, use Admin to pause new activity for the exact city/service.
3. Preserve and support active work; do not cancel it automatically.
4. Mark the failed step, failure stage, safe note, critical flag, and non-secret evidence reference.
5. Create an incident, support ticket, both, or neither based on operational need.

Critical examples include safety concerns, data exposure, payment anomaly, uncontrolled assignment, repeated crash, incorrect identity, PIN exposure, and assignment-lock failure. An unresolved critical failed/blocked drill prevents Operations-only readiness.

## Rollback

1. Confirm active work is complete or in a safe supported state.
2. An authorised owner changes the affected service to `OFF` through audited Admin controls.
3. Deactivate the affected member or pause the controlled group if identity/supply is implicated.
4. Reconcile payment, earnings, and lock state.
5. Record incident/support references and the owner decision.
6. Reopen the drill only after the failure is understood; repeat failed and adjacent steps.

Do not delete audit history, recreate identities, expose secrets, enable automatic matching/payouts, or promote another city based on the failed city's evidence.
